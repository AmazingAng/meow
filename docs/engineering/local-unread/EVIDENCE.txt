Meow local unread authority — evidence, 2026-10-29

Outcome
The shared iPhone inbox owns read state, unread counts and badges. Local reads
never call read/count HTTP routes. App and NSE share transactional SQLite;
verified receipts preserve local reads, registration isolation and deletions.
The server omits badge values and no longer counts unread rows per push.
Legacy server endpoints remain compatible. CLI/gateway protocol/dependencies,
Go schema v6 and retention defaults are unchanged.

Rollout: update the iPhone app first, then deploy the server. Updated apps strip
old-server badge values; old apps do not implement this local authority model.
No archive, TestFlight upload, deployment, release or real-user push was made.

Acceptance / failure-model mapping
1. Preserve all legacy history/read states; transactional import retries on
   failure, preserves newer shared payloads, and cannot reimport deleted history:
   LocalUnreadStoreTests.testLegacyMigrationPreservesReadStateAndDoesNotImportTwice;
   testMigrationPreservesNewerTargetPayloadAndRetriesAfterFailure;
   testMalformedLegacyDataRemainsIntactAndCanRetryAfterRepair;
   testOldSchemaReadStateIsBackfilledWithoutChangingThePayload.
   The original private database is retained as a logical migration backup,
   not erased or treated as a secure-deletion guarantee.
2. Duplicate receipts, stale remote reads and two independent SQLite connections:
   testTwoConnectionsDeduplicateAndPreserveLocalReadOverRemoteUpdates;
   actual two-OS-process probe in verify_local_unread.py.
3. Deleted messages/old registrations cannot return; identity changes roll back:
   testDeletedAndOldRegistrationReceiptsCannotResurrectMessages;
   testReceiptIdentityChangeRollsBackAndInactiveScopeCannotWrite;
   testResetDuringMigrationCannotReactivateOldRegistration;
   testRegistrationActivatesLocalInboxBeforeReturning;
   existing reset/delta/retention/deletion model tests.
4. Offline single/group/bulk reads, frozen matching selections, atomic recovery
   from unsaved online payloads, no unrelated row decode and no read/count HTTP:
   testOfflineReadAndCountsNeverNeedHTTPAndSurviveRestart;
   testReadTransactionFailureAndGeneratedReplayAreAtomic;
   testReadCannotInsertPendingMessagesOutsideItsSelection;
   testReadingUnsavedOnlineContentCommitsThePayloadAndReadFlagTogether;
   testReadMutationDoesNotDecodeUnrelatedMessageBodies;
   InboxGroupingModelTests and InboxPerformanceTests local-read regressions;
   LocalInboxModelTests offline/older-snapshot/filter tests.
   TEST-CONTRACT-CHANGES.json maps previous network-read contracts to their
   intentionally changed local-only contracts. No read rollback on HTTP failure
   is expected under the user-approved design; storage failure still prevents success.
5. Both push paths save full verified origin records before local counts;
   failed storage/fetch retains safe content; old badge is removed; timeout/
   late callback/identity/expiry cannot update delivered content:
   LocalUnreadDeliveryTests, NotificationLatencyTests, GatewayContentTests,
   NotificationCallbackTests and GatewaySessionTests.
   testBadgeIsReadAfterReceiptWorkRatherThanReusingAnOlderCount explicitly holds
   receipt reporting while the user marks read, then requires the latest count.
6. Server push contains no aps.badge and legacy authorization/API behavior stays:
   TestDirectPushNeverOverridesPhoneUnreadBadge plus full Go race/shuffled suite.
7. Actual simulator shared DB, first remote sync, local badge, full-history
   matching, relaunch, swipe read/delete and Chinese large-type controls:
   UI tests 31, 21, 27 and 30. The fixture reads the simulator's actual App Group
   SQLite in read-only mode and asserts zero read HTTP requests; its server
   cache count is separate. Exported local-unread, swipe and large-Chinese
   screenshots were visually inspected. No new header button was added.

Failures encountered and resolved (not hidden passes)
- Initial store stubs failed as expected, with some missing-temp-folder teardown
  errors; those errors alone are not claimed as assertion RED evidence.
- Direct push RED reproduced aps.badge=0. Initial native model fixture required
  an explicit dictionary type; corrected only the fixture, then red-model-2
  produced 8 behavioral assertion failures in 2 tests.
- Adversarial regressions reproduced import overwriting a newer shared payload
  and missing final direct-notification expiry checks; implementation corrected.
- Legacy network-read/count assertions deliberately conflict with the new local
  contract; replacements are recorded above. The audit also exposed actual
  native Date precision loss and lost dirty online content; both were fixed.
- A held receipt reproduced badge=1 after local read expected 0; count now runs
  after auxiliary receipt/persistence work. An initial test actor-await typo was
  corrected before this behavioral RED.
- Additional RED cases caught retained storage-error feedback after recovery,
  an inactive first-registration inbox, successful reads without durable pending
  payloads, and unrelated-body decoding during read. Each received a regression
  and implementation repair; read flags and pending bodies now commit together.
- final-1 verifier initially mistook Go packages with no tests for skipped tests;
  checker now rejects individual-test skips without rejecting empty packages.
- final-2 was superseded and only its owned verifier child processes terminated.
- final-3 passed native/Go/mutants and 282 iOS units, but UI31 caught a real empty
  inbox: hydrated empty local state incorrectly suppressed initial remote sync.
  hasSyncedInbox now distinguishes remote sync from local load. The same UI
  assertions pass in final-4, with 283 units including the added regression.

Limits
- No physical phone/APNs, TestFlight, production network or iOS 17 runtime check.
  No Swift TSAN, power-loss/hardware-corruption rehearsal or randomized XCTest
  scheduling. SQLite rollback/failure/restart/migration/process cases do not prove
  all OS termination timings or filesystem failures.
- Background badges are best-effort: NSE execution/fetch/lock/deadline failure
  can leave the old count until app entry reconciles it. No cross-device read sync.
- Test-only temp SQLite teardown emits existing vnode-unlinked/file-descriptor
  warnings; all final assertions pass. Build output also includes existing unused
  result/AppIntents metadata warnings. No warning was relabeled as a test pass.
- Source-specific earlier verifiers/evidence describe their own older contracts.
  Use this entry point for the current local-read architecture. Build caches can
  be regenerated; ignored final logs/reports/screenshots/xcresult remain local.
