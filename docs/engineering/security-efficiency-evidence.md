## RED and checker controls

Before the fixes, isolated review tests reproduced IPv6 registration bypass,
private-body debug logging and lost provider/gateway cooldowns. The review's
503/120-second example was strengthened to 1200 seconds so it also verifies a
provider delay longer than the new 15-minute floor.

Native RED fixtures then demonstrated repeated parsing (three cases/five
assertions), absent durable page/checkpoint behavior (three cases/seven
assertions), repeated full sync (two cases/13 assertions), and repeated local
decoding (one case/two assertions). Initial native harness extraction lacked
`InboxProjection`; after adding the unchanged source, behavioral failures were
observed. One early native full run failed because SwiftPM has no app Info.plist;
the harness now supplies the actual shipped default at the Bundle boundary,
without modifying production configuration parsing. A byte-budget fixture was
corrected before implementing the cache, then observed failing again.

The verifier requires each manual mutant to execute and fail its **named
behavioral test**; a compiler/import failure is not a kill. It restores copied
Swift files and reruns the native suite. Mutations never touch production source
or real data. Migration-failure and legacy-resolution tests were added after
implementation and are checked by corresponding mutants, rather than claimed as
new pre-implementation RED observations.

The first aggregate verifier stopped while scanning newly generated Python
bytecode as UTF-8. Its earlier checks were not reported as a complete pass.
Only this run's four generated bytecode files were removed, and the verifier
disables bytecode generation before importing its helpers. The final aggregate
run is recorded below.

fail. These are not claims of complete branch coverage. UIKit, notification
center, Keychain and Bundle boundaries are adapted in the native package;
the actual iOS SDK build and simulator exercise production app sources.

## Delivery and limits

- Source fixes only; no CLI release, TestFlight upload or production deployment.
- Server/gateway deployment is needed for rate-limit, diagnostic, cooldown and
  incremental-sync changes. Schema **v8** requires a pre-upgrade online backup;
  an older binary cannot open it. Restore that snapshot for rollback, retaining
  the upgraded database separately.
- A new iOS build is needed for preview caching and incremental sync. Existing
  clients retain ordinary inbox pagination; updated clients support old servers
  through their existing full-history path. CLI sending needs no update.
- Server restart/restore intentionally causes one safe backfill. Retry deadlines
  and attempt counts remain in memory; restart does not preserve cooldowns.
- Server omission/expiry is not a phone deletion signal. There is no new
  cross-device tombstone synchronization, automatic local retention or approval
  execution. Local read state remains authoritative.
- Simulator and mock-provider results do not prove real APNs display or physical
  device behavior. No real pushes or credentials were used. Performance timings
  are an isolated local benchmark, not an end-to-end latency or RSS guarantee.
