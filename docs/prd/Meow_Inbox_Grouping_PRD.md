# Meow iOS：收件箱分组浏览

版本 0.2 ｜ 2026-10-23 ｜ 状态：已实现，自动化验证通过，待真机验收 ｜ 范围：仅 iOS 主 App，不改 CLI、服务器及系统通知分组

## 1. 背景

同时使用多个 Agent、项目和会话时，收件箱中的结果混在一个列表里，难以快速查看某个会话或项目的进展。

本功能在 App 本地提供不同浏览方式。用户也可以将当前视图中的任意多个组手动合并，按自己的习惯整理消息。

## 2. 目标与非目标

目标：

- 支持“消息、会话、项目、来源”四种浏览方式；来源包括 Agent 和其他发送通知的服务。
- 分组列表 → 组内消息 → 消息详情，逐级进入和返回。
- 会话、项目、来源视图各自支持多选合并与解除合并，各视图规则互不影响。
- 先基于全部本地消息分组，再对展示结果分页。
- 保留本地历史，不因服务器缓存过期删除消息或分组。
- 不新增服务器接口和字段，旧消息继续可见。

非目标：

- 不修改系统横幅、锁屏或通知中心的分组行为，不新增按 session 叠放，不为分组新增通知回源请求。
- 不重新引入审批、待回答或问题处理状态。
- 不修改消息中的 source、workspace、session 元数据，不同步用户的合并规则到服务器或其他设备。
- 不做分组置顶、静音、自定义重命名或分组提示音。

## 3. 可用数据与术语

通知可以携带可选的 context，App 对应 NotificationOrigin。字段可能缺失，不能假定每条通知都具备完整来源信息。

| 字段 | 内容 | 本功能用途 |
| --- | --- | --- |
| source | 发送来源的自由文本，如 Claude Code、Codex、GitHub Actions | 来源分组；会话身份的一部分 |
| context.workspace | 项目显示名；Agent 默认使用工作目录的文件夹名 | 项目按名称分组 |
| context.workspace_id | 项目身份；Agent 默认提供规范化工作目录路径的哈希 | 区分会话所属的 workspace；不用于拆分同名项目组 |
| context.session | 会话名称；随发送时可取得的名称写入通知 | 会话名称分组及显示 |
| context.session_id | 会话 ID | 仅在缺少会话名称时提供兜底身份及短 ID 标签 |
| event | 可选的 result、attention、failure | 分类图标；未读提醒标记 |

名称是通知发送时的快照。App 不主动向 Agent 查询外部改名。老消息可能没有 context；其他服务和手动发送的消息也可以只提供部分字段。

所有分组和合并规则限定在当前服务器／设备注册作用域内，不跨服务器或设备注册混用。

## 4. 浏览方式与默认分组

### 4.1 入口和展示偏好

- 入口在收件箱顶部导航栏菜单，选项为“消息、会话、项目、来源”。
- 默认是“消息”，沿用现有消息列表行为。
- 浏览方式保存在本机，重启保持；切换服务器保留浏览方式，但清除旧组页面、选中项及旧搜索上下文。
- 合并规则按服务器／设备注册作用域分别保存，切换服务器不会将旧规则应用到新消息。

### 4.2 基础分组规则

| 方式 | 基础分组身份 | 组名 | 副信息 |
| --- | --- | --- | --- |
| 消息 | 不分组 | — | — |
| 会话 | 来源 + workspace 身份 + 会话名 | 会话名 | 项目 · 来源 |
| 项目 | workspace 项目名 | 项目名 | 组内来源；数量较多时截断并显示总数 |
| 来源 | source 来源名 | 来源名 | 最近活跃的项目；没有项目时省略 |

身份和缺失字段的规则：

1. 名称去除首尾空白，保留大小写；不自动推断别名或近似匹配。
2. 来源为空时使用统一的 Meow 来源身份和标签。
3. workspace 身份优先用 workspace_id，没有 ID 时用 workspace 名；两者都没有时使用明确的“未知 workspace”身份。
4. 会话有名称时，按“来源 + workspace 身份 + 会话名”分组。即使 session_id 不同，只要这三个组成部分相同，就属于同一个命名会话组。
5. 会话没有名称但有 session_id 时，按“来源 + workspace 身份 + 会话 ID”兜底，显示“会话 · 短 ID”。名称身份与 ID 身份使用不同类型，避免字符串恰好相同时误合并。
6. 既没有会话名也没有会话 ID 的消息，在会话视图进入“未归类”。缺少项目名的消息，在项目视图进入“未归类”；即使有 workspace ID，也不猜测项目名称。
7. “未归类”是保留身份，不能与用户实际命名为“未归类”的组混淆。
8. 分组 key 使用结构化组成部分，不采用可能产生歧义的直接字符串拼接。

产品语义：

- **同名项目直接合并展示**：不同路径、不同 workspace ID、不同 Agent，只要项目名相同，都在同一个项目组。git worktree 也遵循此规则。不增加短 ID 后缀或父目录标签。
- **项目视图与会话视图各自分组**：项目视图按名称合并，不会抹去会话视图中的 workspace 身份。同一个来源在两个不同 workspace 中使用相同会话名，仍是两个会话组。
- 会话名称参与身份。新通知携带不同会话名时形成新的基础组；旧消息保留原来的名称和归组。需要一起查看时，用户可以手动合并这些组。原本缺名而按 ID 兜底的组，后续出现名称时也遵循这一规则。
- 只有名称、没有 ID 的元数据无法可靠区分现实中同名的多个对象，按上述规则合并，不补造身份。

### 4.3 手动合并和解除合并

- 在会话、项目或来源视图进入“选择分组”，选择至少两个组，点击“合并分组”。支持一次合并任意多个组。
- 选择操作针对当前视图；不跨视图混选。会话视图中的合并不影响项目视图或来源视图，消息视图不提供分组合并。
- 合并发生在当前作用域内，只影响本机展示，不重写或删除消息及元数据。
- 合并规则记录基础组身份集合，不仅记录当前命中的消息 ID。因此成员组今后收到的新消息仍进入合并组。
- 搜索或未读筛选下选择合并时，合并的仍是所选组的完整成员身份；筛选只决定当前可见消息，清除筛选后显示合并组的全部消息。
- 已合并组可以与其他组再次合并。成员身份取并集并去重，不产生嵌套合并组，同一视图内每条消息只出现一次。
- 合并组显示自动生成的名称，例如“A、B 等 3 组”；完整成员在组信息中查看。单个名称过长时截断，不新增自定义命名流程。
- 组信息提供“解除合并”，恢复为各基础组；不改变已读状态或删除消息。再次合并后的解除操作恢复为全部基础组，不恢复更早的嵌套结构。
- 合并规则及合并组的本地稳定 ID 持久化保存，重启后保持。组排序变化、搜索和未读筛选不修改规则。
- 组在搜索下暂时不可见时不解除合并。成员中的最后一条本地消息被删除后，空成员不显示；整个合并组无本地消息时不显示，但保留规则，以便后续匹配的新消息继续归组。清除该作用域的全部本地数据时，同时清除其合并规则。

## 5. 数据处理、列表与导航

### 5.1 全量本地分组和分页

处理顺序固定为：

~~~
当前作用域的全部本地消息
  → 建立基础组及稳定的组信息
  → 应用当前视图的本地合并规则
  → 在组内应用搜索和“全部／未读”筛选
  → 隐藏无匹配消息的组，计算匹配摘要、未读数和排序
  → 对组列表分页展示
~~~

- 不从现有仅展示前 50 条的 model.notifications 生成分组；使用全部本地消息作为输入。
- 一级页按组分页；二级页独立按该组匹配的消息分页。
- 分页只限制渲染数量，不限制组成员、未读统计、搜索范围或批量已读的作用范围。
- 消息视图继续使用现有分页方式。

### 5.2 一级页：分组列表

每组一行，展示组名、副信息、最新匹配消息的分类图标和正文摘要、时间、匹配消息中的未读数。

- 摘要最多两行，复用现有 Markdown 摘要处理；不重新把 New result、Needs your attention 等通用类别标题作为组名。
- 组内有未读的 event=attention 或 event=failure 消息时显示提醒标记。仅依据显式事件字段，不从标题猜测，不表示存在等待批准的问题。
- 按最新匹配消息的时间倒序；时间相同时使用稳定身份作为次级排序条件。
- 无对应副信息时省略，不补造项目或来源信息。

组信息和颜色：

- 组名、副信息及基础颜色从完整组确定，不随搜索命中某一条旧消息而改变。
- 项目组颜色由项目名称确定，与最新消息来自哪个 Agent 无关。
- 会话组颜色由来源、workspace 身份和会话身份确定，同一来源及 workspace 的会话保持相近色系。
- 来源组颜色由来源身份确定。
- 手动合并组使用本地稳定 ID 决定颜色，不随成员顺序或最新来源变色；二级页每条消息保留自身来源配色。
- 颜色只作辅助，组名和来源等文字仍可辨识，兼顾深色模式、动态字号及 VoiceOver。

### 5.3 二级页：组内消息

- 顶部显示组名和副信息；合并组可查看成员及解除合并。
- 列表按匹配消息的时间倒序；同一时间使用消息 ID 作稳定次级排序。
- 复用现有消息行，保留 session 名、项目和来源信息；同名项目组中可以包含多个 workspace 的消息。
- 左滑删除单条消息，沿用现有服务器与本机删除行为。
- 点击消息进入现有详情页，返回回到该组，保留浏览上下文。
- 打开组页面本身不会把整组消息标为已读。
- 现有收件箱 header 的按时间范围删除保持全局语义，不在组页复用成含义不清的“删除本组”操作。本版不新增整组删除。

### 5.4 搜索和筛选

- 保留现有可见的“全部／未读”，不恢复“待处理／待回答”。
- 搜索覆盖完整本地消息的标题、正文、来源及已有 context 搜索字段，包括会话名和项目名。
- 一级页只显示存在匹配消息的组；摘要、时间及未读数按匹配消息计算。搜索中显示“匹配未读数”，避免与全局角标混淆。
- 组身份、组信息、颜色和合并成员不受搜索、筛选影响。
- 从一级页进入组页时保留搜索和筛选；清除条件后可看到该组全部本地消息。
- 搜索无结果显示“没有匹配的消息”；未读筛选无结果沿用“全部已读”。清除筛选可以找回暂时隐藏的组。

### 5.5 实时更新、本地历史与空状态

- 新消息、已读变更、删除和同步完成后，一级页和二级页更新。
- 停在组页时，匹配的新消息加入顶部，不跳转、不自动标为已读；用户正在阅读较旧消息时不强制滚回顶部。
- **服务器缓存过期不会删除手机历史，也不会让组消失。** 同步中服务器不再返回某条消息，不表示删除本地记录。
- 最后一条本地消息被用户删除或本地数据被清除后，该组才实际消失。搜索无匹配、未读归零只表示在当前条件下暂时隐藏。
- 当前组已无消息或当前条件下无匹配时，组页显示对应空状态，不自动退出页面；允许返回或清除筛选。
- 切换服务器或设备注册时清除旧页面和进行中的选择操作；异步操作结果不能应用到新作用域。

### 5.6 从系统通知打开

- 沿用现有行为，点击系统通知直接打开该条消息的详情。
- 从系统通知打开的详情返回收件箱当前浏览方式；不额外插入一层组页。
- 系统通知不受 App 的浏览方式或手动合并规则影响。

## 6. 已读操作

提供两个明确区分的操作：

| 操作 | 入口 | 作用范围 |
| --- | --- | --- |
| 将匹配消息标为已读 | 当前组页 header／操作菜单 | 当前组在当前搜索、筛选下全部匹配的未读消息，包含尚未分页显示的消息 |
| 全部标记为已读 | 收件箱 header 菜单 | 当前服务器／设备作用域的全部消息，包含其他组及搜索、筛选未命中的消息 |

- 全局按钮在搜索或筛选期间也明确显示“全部消息”，不能与当前组的匹配操作混淆。
- “将匹配消息标为已读”在操作开始时固定消息 ID 集合；操作期间新收到的消息不自动加入本次集合。
- 合并组的匹配操作覆盖其所有成员中匹配的未读消息，不影响其他组或其他视图中不属于该集合的消息。由于消息本身的已读状态共享，其他视图对同一消息的统计相应更新。
- 组内匹配操作复用单条已读 API，限制并发。批量成功项保留结果，失败项立即回滚本地乐观更新，并汇总提示失败数量及重试入口，不等待下次同步才反馈。
- 已超出服务器缓存的本地历史消息，单条已读返回 404/not_found 时视为本地已读成功，不删除历史，不恢复为未读。
- 全局已读沿用现有全局已读接口及本地历史处理；网络失败给出提示。不得将它用于模拟某一组的匹配操作。
- 请求进行中防止重复提交；服务器切换后的旧操作结果不更新新作用域的消息或角标。

## 7. 系统通知与兼容性

- 本版只做 App 内分组。系统横幅、锁屏与通知中心保持现有行为，不新增按 session 分组，不修改现有 thread-id／threadIdentifier。
- 不为分组修改通知扩展、网关协议、APNs payload 或直连回源逻辑，不增加推送请求。
- 旧服务器、旧 CLI、缺少 context 或 event 的消息都能浏览，按缺失字段规则进入来源组或“未归类”。
- 分组和合并不新增网络请求。同步、单条／全局已读及删除继续使用现有接口。
- 本地历史、浏览偏好和合并规则不跨设备同步；切换浏览方式不改变通知内容、已读状态或服务器数据。

## 8. 本地化和可访问性

新增文案提供英文和简体中文，加入现有 String Catalog，包括浏览方式、未归类、会话短 ID、多选、合并、解除合并、成员说明、匹配消息已读、全部消息已读及部分失败提示。

VoiceOver 应能读出组名、组类型、成员数量、匹配未读数、提醒标记、选中状态，以及合并／解除合并的操作含义。大字号下名称、未读数与按钮不能重叠，长名称可换行或截断并保留完整可访问性标签。

## 9. 验收标准

1. 默认“消息”视图，保留现有行为；其他浏览方式和选择偏好重启后保持。
2. 来源相同、会话名相同但 workspace 身份不同的消息，在会话视图分开；三者相同即使 session ID 不同也合并。
3. 会话缺少名称时按 ID 兜底；名称身份、ID 身份及“未归类”保留身份不碰撞。
4. 不同路径／workspace ID／Agent 的同名项目在项目视图合并，不显示 ID 后缀；会话视图仍保留 workspace 区分。
5. 会话名称变化后按命名规则形成新基础组；可手动合并新旧组。搜索旧消息不会改变已有组的身份、标签或颜色。
6. 每个分组视图可以多选至少两个组进行合并，支持多个基础组及已有合并组再次合并，不重复显示消息。
7. 会话、项目、来源的合并互不影响，重启后保留；解除合并恢复基础组，不丢消息、不改已读状态。
8. 合并后的新消息自动进入对应成员所在的合并组。搜索无匹配时规则不丢失，清除条件后重新显示。
9. 使用超过 50 条、覆盖多个旧项目的本地数据验证：一级页组数、未读数、搜索与合并覆盖全部本地消息，不受消息展示分页限制。
10. 一级页按最新匹配消息时间稳定排序；组内消息独立分页。新消息到达不跳页、不强制滚动、不自动标为已读。
11. 搜索和“全部／未读”筛选只影响展示和匹配统计，不重新引入审批状态。
12. 组页批量已读只处理操作开始时的匹配消息，包含未分页显示的匹配消息；其他消息及期间新到消息保持原状态。
13. 收件箱 header 的“全部标记为已读”覆盖当前作用域的全部消息，不受组、搜索和筛选限制，不影响其他作用域。
14. 部分已读请求失败时成功项保留、失败项回滚并提示；服务器缓存过期的历史消息可本地标为已读，重启后保持。
15. 服务器缓存过期及后续刷新、App 重启后，本地历史和对应分组仍存在；删除最后一条本地消息后该组才消失。
16. 组列表 → 组页 → 详情可逐级返回；系统通知直达详情后返回当前收件箱视图。组清空、筛选清空及切换服务器时不出现旧页面串组。
17. 同名项目中交替收到不同 Agent 的消息，项目组颜色不跳变；合并组颜色不随成员排列或最新消息变动。
18. 旧消息和元数据缺失的消息在全部浏览方式下均可找到，不因分组被删除；“未归类”可参与合并和解除合并。
19. 系统通知和通知扩展行为保持现状，不为本功能新增网络请求或 session 叠放规则。
20. 英文、中文、VoiceOver、动态字号和深色模式完整。单元测试覆盖分组身份、缺失字段、合并／解除、分页前分组、筛选统计、颜色稳定及操作作用域；集成测试覆盖已读失败、404、本地保留和服务器切换。

## 10. 实现约束与后续范围

- 分组、合并和聚合应使用可独立测试的数据层逻辑，避免在 SwiftUI 每个行的渲染过程中重复扫描全部消息；多次搜索、切换模式和大量历史下不能阻塞主线程。
- 合并规则使用可持久化的稳定身份；不能使用进程间不稳定的临时 hash 值。组名、预览和计数是派生信息，不另建与消息历史不同步的事实来源。
- 本功能不承诺恢复历史消息从未携带的元数据。名称相同导致的自然合并、命名变化产生新组按第 4.2 节执行，用户可通过手动合并整理。
- 后续可以独立评估分组置顶、静音、自定义名称及偏好同步，不作为本版接入条件。
