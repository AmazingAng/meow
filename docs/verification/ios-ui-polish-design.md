# iOS 界面优化

本轮依据 Apple 的 [Alerts](https://developer.apple.com/design/human-interface-guidelines/alerts)、[Sheets](https://developer.apple.com/design/human-interface-guidelines/sheets)、[Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility) 指南调整实际 SwiftUI 界面。

## 交互约定

- 更换服务器、放弃待发送回复、创建新密钥：使用系统 Alert 确认关键后果，提供标准“取消”，危险操作单独标红。提示简短，不用带箭头的长文案弹出菜单。
- 编辑服务器：使用可伸展的系统 Sheet，左侧取消、右侧保存。大字体使用完整高度。格式错误留在输入框下方，先收起键盘，便于看见和修改。
- 文本回复：输入区固定在键盘上方，与正文独立布局；最多显示三行，更多内容在输入框内滚动。发送按钮具备 48pt 的实际点击范围。收起键盘保留草稿。
- 详情页：收起底部 Tab；问题、截止时间和回答操作组成清晰区域；普通通知不出现回复操作。等待联网发送用明确状态说明，不用持续旋转假装正在传输。
- 收件箱：筛选独立于空状态，横向滚动适配大字体，点击区域至少 44pt。选中项同时使用对勾和底色；待处理问题显示文字状态，不只依赖红点。
- 设置：连接、通知权限、设备密钥和安全操作分组；创建新密钥放在独立安全分组。
- 引导：正文可滚动，主要操作保留在安全区域。字体随系统设置变化，减少动态效果设置会关闭过渡动画。

## 保持的行为

后端、凭证存储和回复队列实现不变。取消服务器确认保留身份和待发送回复；明确放弃才清除队列并重新注册。旧服务器已经处理的回答无法撤回。App 仍为竖屏 iPhone 应用。

## 验证要求

实际模拟器检查系统 Alert 类型和居中位置、操作可点击、筛选与空状态不重叠、键盘出现后发送按钮仍可点击、收起键盘保留草稿，以及中英文和小屏大字体深色模式。既有离线队列、重启、回复结果的真实 API 验证继续保留。
