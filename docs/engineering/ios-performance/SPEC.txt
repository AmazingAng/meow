Acceptance / failure model
1. Message projection: full local filtering/search/urgency projection runs off
   MainActor once per revision/query/filter; getters only slice cached results.
   Superseded work cancels and cannot publish stale/foreign-scope results.
   Preserve local search fields, ordering, complete-history filtering before
   pagination, legacy expiry and existing per-view merging. During projection
   show progress, never a false no-results state or actionable stale rows.
   Existing same-stack search assertions will await local projection completion;
   retain all expected records and the no-network assertions (not a debounce or
   server search). UI tests wait for visible results as before.
2. Synchronization: overlapping refresh callers share a single sync task;
   cancellation/registration switch invalidates and cancels it. A verified
   foreground notification fetches its one record, not all history. Initial,
   manual and foreground sync still reconcile the complete server cache with
   independent phone history. Preserve mutation/deletion races and empty-cache
   history. No notification omission may delete saved messages.
3. Durable deltas: local changes encode/write only affected IDs and explicit
   tombstones; unchanged full-sync rows are not reserialized. Retain serial
   ordering, atomic patches, scoped erase, retryable dirty changes after failure,
   and latest-version acknowledgements so a stale write callback cannot clear
   newer pending state. Full snapshot save remains for explicit callers/tests.
   Add a local scope/time/ID index without deleting old data.
4. Selected reads: add POST /v1/inbox/read-selected with 1..200 notification IDs,
   device-token auth, own-device scope only, duplicate-safe and idempotent;
   return {marked: N}, treat absent/expired IDs as no-op. Never mark unselected
   rows or disclose another device's records. No server schema migration.
   App freezes selected unread IDs, applies/persists optimistic state once,
   skips known local-only history, chunks remote IDs, respects Retry-After and
   rolls back only failures. An unsupported 404/405 route falls back to existing
   per-ID reads; never reuse the unrestricted mark-all endpoint for a selection.
5. Extension: hydrate/validate origin first. Counts and delivery reporting run
   concurrently within one 250ms auxiliary budget, then finish exactly once.
   Timeout does not wait for cancellation-ignoring network closures. Ignore late
   auxiliary results; always recheck registration at final display. Retain safe
   fallback on hydration failure and OS expiry. Reports remain best-effort and
   may be interrupted by extension termination. Test metadata concurrency,
   deadline, cancellation, identity change and late completion.
